## What changed from the earlier repository version

| Area | Earlier GOLD_AI version | Current AZT implementation |
|---|---|---|
| Desktop apps | Legacy GOLD_AI interfaces | Branded AZT Admin/Client workspaces with dashboard, clients/accounts, trades, journal, messages, settings and manual payments |
| Owner launch | Backend started separately in command windows | One visible Admin window supervising hidden API, signal, Telegram and optional personal/hosted workers, with file logs and clean shutdown |
| Personal trading | Separate/limited owner execution flow | Explicit personal MT5 Start/Stop, independent of customer registration/subscription, account identity and shared-process protections |
| Client accounts | Earlier client execution flow | Multiple authorized MT5 accounts with separate terminals, desired Start/Stop state, reconnect handling and account-scoped views |
| Execution safety | Previous timestamp/status issues and less resilient dispatch | True UTC broker clock handling, 20-minute stale/60-second future rejection, no backlog on start/reconnect, durable claims, no automatic replay after uncertain execution, Windows atomic status-write retries |
| Client policy | Existing upstream client and licensing | Upstream history merged; strict selected per-trade risk policy and absolute 2% ceiling retained; owner-side dispatch reconciliation added |
| Subscription/payment flow | Earlier admin/subscription controls | Local-date display, expiry/reminders and manual proof submission/approval; no invented automatic payment verification, pricing or referral percentage |

The latest owner update, specifically `9290e84` → `8cfb0ed`, adds readable Telegram execution alerts, detailed paginated `/positions` and `/journal`, native-currency SL/TP estimates, closed-trade and observed SL-update cards, and independently reloadable Telegram workers. Before it, Telegram included raw execution IDs, thin position/journal text and Telegram code frozen into the EXE. An observed stop change is only called trailing when its source is known. Existing strategies, risk/news controls, subscriptions and duplicate/backlog protections are preserved.
